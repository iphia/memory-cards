# 다섯 번 · 암기 카드

설치나 빌드가 필요 없는 GitHub Pages용 웹앱입니다. `index.html`을 열면 바로 사용할 수 있습니다.

## 사용 방법
- 예시 키워드 묶음: **임병찬 / 독립의군부**, **박상진 / 대한광복회** (각 키워드는 한 줄씩 입력)
- 한 카드에 A, B, C, D, E를 각각 한 줄씩 입력하면 하나가 무작위 문제로 선택됩니다. 예: 문제 B → 정답 A, C, D, E를 각각 별도 줄로 표시합니다. 정답에는 선택된 키워드를 제외한 나머지가 입력 순서대로 표시됩니다.
- 개별 등록과 클립보드 등록 모두 엔터로 키워드를 구분합니다. 빈 줄은 무시하며 2~200개의 서로 다른 키워드가 필요합니다. 키워드 중간의 하이픈은 그대로 유지됩니다.
- `-C`, `C-`처럼 앞이나 뒤에 하이픈을 붙인 키워드는 정답 전용입니다. 문제 후보에서는 제외되고 정답에는 하이픈 없이 표시됩니다. 문제로 쓸 키워드가 하나 이상 필요합니다.
- 정답을 보거나 가릴 때는 문제 키워드가 바뀌지 않습니다. 이전·다음 이동이나 새로고침에도 현재 순서의 문제 키워드를 유지합니다. 한 바퀴를 끝내면 문제 키워드를 다시 무작위로 선택합니다. 이전과 같은 키워드가 나올 수도 있습니다.
- 정답 횟수는 키워드별이 아닌 카드 묶음 단위로 기록됩니다.
- 학습 카드를 0.55초 이상 길게 누르면 해당 카드의 별도 수정창이 열립니다. 스크롤하거나 드래그하면 길게 누르기는 취소됩니다.
- 카드를 누르면 정답이 나타나고, 다시 누르면 가려집니다. 정답을 확인한 뒤 O 또는 X를 누릅니다.
- 문제로 나올 수 있는 모든 키워드에 각각 O를 눌러야 현재 정답 횟수와 누적 정답 횟수가 1 증가합니다. 이번 바퀴에서 현재 정답 횟수가 5회 이상이 되어도 바퀴가 끝날 때까지 덱에 남습니다. 이전·다음으로 돌아가 정답을 취소할 수 있으며 다음 바퀴를 시작할 때 5회 이상인 카드를 제외합니다. 누적 정답 횟수가 아닌 현재 정답 횟수를 기준으로 합니다.
- 마지막으로 키워드 묶음을 완성한 시점부터 설정한 간격(기본 24시간)마다 현재 정답 횟수가 1 감소하며 최솟값은 0입니다. 다음 묶음을 완성하면 감소 시점은 그때부터 설정한 시간 뒤로 갱신됩니다. 일부 키워드의 O만으로는 감소 시점을 바꾸지 않습니다. X와 카드 이동은 이 시점을 바꾸지 않습니다.
- 앱을 닫아 둔 동안에도 경과한 설정 간격만큼 다음 접속 시 반영합니다. 누적 정답 횟수는 감소하지 않습니다. 진행 막대는 5회를 목표로 표시하며 현재 정답 횟수가 4회 이하로 줄어들면 다시 학습할 수 있습니다. 이전 버전에 저장된 6회 이상 카드도 횟수를 유지하며, 감소하여 4회 이하가 되면 다시 나옵니다.
- 학습 가능한 카드를 한 바퀴 돌면 Fisher–Yates 방식으로 순서를 무작위로 섞습니다. 우연히 이전과 같은 순서가 나올 수 있습니다.
- 이전·다음 버튼으로 채점 없이 카드를 이동할 수 있습니다. 이동하면 정답은 가려지고 정답 횟수는 변하지 않습니다. 첫 카드에서는 이전 버튼을 누를 수 없습니다. 마지막 카드에서는 다음 바퀴 버튼으로 순서를 섞고 새 바퀴를 시작합니다.
- 기존 기록이 있어도 박상진 예시가 한 번 추가됩니다. 삭제한 예시는 다시 추가되지 않습니다.
- 카드 관리의 검색창에 입력하면 모든 키워드에서 실시간으로 검색합니다. 영문 대소문자는 구분하지 않으며 검색어를 지우면 전체 카드가 표시됩니다.
- 카드 관리를 통해 내용을 추가·수정·삭제할 수 있습니다. 목록의 수정 버튼을 누르면 별도 수정창이 열립니다. 키워드를 바꾸고 수정 저장을 누르세요. 저장하지 않고 닫으면 기존 내용은 유지됩니다. 수정 시 다음 감소 시각은 유지됩니다. 5회 이상 카드에 새 문제 키워드가 생기면 현재 정답 횟수는 4회가 되며, 그대로 남은 기존 문제 키워드는 정답 처리합니다. 삭제하면 해당 학습 기록도 삭제됩니다.
- 정답 보기: Enter / Space, 채점: O / X.
- 기록은 현재 브라우저의 localStorage에 저장됩니다. 다른 기기·브라우저나 로컬 파일과 배포 사이트 사이에서는 공유되지 않습니다. 브라우저 데이터를 지우면 기록도 지워집니다.

## GitHub Pages에 올리기
1. GitHub에서 새 **Public** 저장소를 만듭니다. 예: `memory-cards`.
2. **Add file → Upload files**로 `index.html`, `style.css`, `app.js`를 저장소 최상위에 올리고 Commit changes를 누릅니다. 폴더 자체가 아닌 폴더 안의 파일을 업로드하세요.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. Source: **Deploy from a branch**, Branch: **main**, 폴더: **/(root)** 를 선택하고 Save를 누릅니다.
5. 배포가 끝나면 같은 화면의 Visit site에서 접속합니다. 일반적인 주소는 `https://계정이름.github.io/memory-cards/`입니다.

공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 구성
- `index.html`: 한국어 화면
- `style.css`: 모바일·데스크톱 반응형 스타일
- `app.js`: 카드, 채점, 저장, 복습 시간과 무작위 순서 관리

외부 라이브러리와 서버가 필요하지 않습니다. 공개 저장소에 올린 소스의 예시 내용은 공개됩니다. 앱 화면에서 직접 추가한 내용은 현재 브라우저에만 저장됩니다.

## 백업 및 복원
- 카드 관리 → 설정 → 백업 다운로드: 모든 키워드 묶음, 정답·오답 횟수, 다음 정답 횟수 감소 시각, 카드 순서와 현재 위치를 JSON 파일로 저장합니다. 저장하지 않은 입력 내용은 포함되지 않습니다.
- 카드 관리 → 설정 → 백업 파일 복원: 이 앱에서 받은 JSON 파일(최대 10MB)을 선택하고 덮어쓰기를 확인합니다. 현재 데이터는 합쳐지지 않고 교체됩니다. 필요하면 먼저 현재 데이터를 백업하세요.
- 다른 기기에서도 백업 파일을 선택해 기록을 옮길 수 있습니다. 자동 동기화는 아닙니다.
- 복원 시 다음 감소 시각을 유지하고, 파일을 보관한 동안 지난 감소 간격도 반영합니다. 이전 버전의 백업도 복원할 수 있습니다.
- 파일 형식이 잘못되었거나 복원을 취소하거나 저장에 실패하면 기존 기록은 유지됩니다.

## 클립보드에서 여러 카드 추가
카드 관리 → 클립보드에서 추가를 누르면 복사한 내용을 읽어 미리 보여줍니다. 추가할 개수와 내용을 확인한 후 **N개 추가**를 눌러 저장합니다. 취소하면 추가되지 않습니다.

키워드는 엔터로, 카드는 `/`로 구분합니다. 예를 들어 아래 내용은 카드 2개가 됩니다. 쉼표와 키워드 중간의 하이픈은 그대로 유지합니다. `/`가 포함된 키워드는 개별 등록을 사용하세요.

```text
윌슨
-민족자결주의
/
이봉창
윤봉길
한인애국단-
```

첫 카드의 문제는 항상 윌슨이고, 두 번째 카드의 문제는 이봉창 또는 윤봉길입니다. 정답 전용 키워드는 나머지 키워드들과 함께 정답에 포함됩니다.

브라우저에서 클립보드 읽기를 지원하지 않거나 권한이 거부되면 직접 붙여넣기 입력란을 사용할 수 있습니다. 한 번에 최대 200개·100,000자까지 처리하며, 형식이 잘못된 항목이 있으면 수정 후 다시 확인해야 합니다. 기존 카드와 학습 기록은 유지되며 같은 내용도 새 카드로 추가됩니다.

## 카드 관리 탭
카드 관리 기능은 목록·검색, 카드 추가, 여러 카드 추가, 설정 탭으로 나뉩니다. 목록·검색 탭에서 카드별 현재 정답 횟수와 5회 목표 진행도, 누적 정답 횟수, 학습 상태와 다음 감소 시각을 함께 확인할 수 있습니다. 검색 결과에도 같은 진행도가 표시됩니다. 목록에서 수정을 누르면 별도 수정창이 열리고, 기존 관리 탭과 추가 중인 입력은 유지됩니다. 탭을 바꿔도 입력 중인 내용은 유지됩니다. 탭에 초점이 있을 때 좌우 화살표 또는 Home/End로 이동할 수 있습니다.

## 이전 학습 기록 전환
기존 카드와 누적 정답 기록을 유지합니다. 기존 복습 예정 시각을 첫 감소 시각으로 사용하며, 현재 정답 횟수가 5회 이상이면 학습에서 제외됩니다. 과거 정답 시각이 저장되지 않은 카드는 업데이트 후 첫 실행부터 24시간 뒤에 감소를 시작합니다.

기존 질문·정답 카드는 두 키워드 카드로 자동 전환됩니다. 기존 텍스트 안의 쉼표·하이픈은 추가 분리하지 않습니다. 카드 ID, 정답·오답 횟수와 감소 시각을 유지하며, 이전 버전(1·2) 백업도 같은 방식으로 복원합니다. 새 백업은 정답 전용 설정을 포함한 버전 11 형식으로 저장됩니다. 버전 3 백업의 키워드도 그대로 복원하며, 기존 키워드는 모두 문제 후보로 유지합니다.

몇 번째 바퀴인지는 표시하거나 저장하지 않습니다. 카드 목록의 끝에 도달하면 순서를 무작위로 섞고 이어서 학습합니다.

카드 목록 끝에서 다음 카드로 이동하거나 X를 누르면, 순서를 섞으며 짧은 카드 애니메이션을 재생합니다. 일반 카드 이동이나 정답 표시에는 재생하지 않습니다. 기기의 동작 줄이기 설정이 켜져 있으면 애니메이션을 생략합니다.

## 감소 시간 설정
카드 관리 → 설정에서 **24시간(기본) / 18시간 / 12시간**을 선택하면 자동 저장됩니다. 변경 직전까지의 감소는 기존 간격으로 반영하고, 남아 있는 현재 정답 횟수는 변경 시점부터 새 간격으로 감소합니다. 0회 카드는 다음 묶음 완성부터 적용됩니다.

백업·복원도 설정 탭에 있으며 감소 시간 설정을 함께 보관합니다. 이전 버전(1~4) 백업을 복원하면 기본 24시간을 적용합니다.

같은 순서에서 이미 O를 누른 카드는 돌아와도 다시 O를 누를 수 없습니다. 한 바퀴를 마치면 이 제한이 해제됩니다. 키워드 선택과 O 처리 여부는 새로고침 및 최신 백업·복원에도 유지됩니다. 카드 내용을 수정하면 해당 카드의 문제 키워드를 다시 선택하고 부분 진행과 이번 순서의 O 처리를 초기화하므로 다시 답할 수 있습니다.

## 줄별 표시와 굵게 표시
키워드는 입력과 정답 표시 모두 한 줄씩 구분합니다. 쉼표는 분리하지 않습니다. `*키워드`, `키워드*`처럼 앞이나 뒤에 별표를 붙이면 문제·정답·관리 목록·클립보드 미리보기에서 굵게 표시합니다. `-*키워드` 또는 `키워드*-`로 정답 전용과 굵게 표시를 함께 지정할 수 있습니다. 표시용 기호는 학습 화면에서 숨깁니다. 키워드 중간의 `*`는 그대로 유지됩니다. 굵게 설정은 수정 및 백업·복원에도 유지됩니다.

## 맞힌 키워드의 출제 제한
문제로 쓸 키워드가 2개 이상인 카드에서 O를 누르면, 그 키워드는 나머지 문제 후보가 각각 한 번 이상 새로 출제될 때까지 다시 뽑히지 않습니다. 나머지는 맞힐 필요 없이 등장하면 됩니다. 정답 전용 키워드는 이 조건에서 제외됩니다. X를 누른 키워드는 다시 나올 수 있습니다.

이전·다음 이동으로 이미 보던 카드로 돌아가면 기존 문제를 그대로 보여주며, 새로운 출제로 세지 않습니다. 카드 순서가 다시 섞일 때도 키워드별 출제 제한은 유지되고, 새로고침과 백업·복원에도 보존됩니다. 띄어쓰기·순서·굵기 등을 포함해 입력 내용을 수정하면 그 카드의 출제 제한을 초기화합니다.

카드 관리의 목록·검색 탭에서 맞혀서 일시적으로 출제되지 않는 키워드 뒤에 **(맞힘 · 일시 제외)**가 표시됩니다. 나머지 문제 후보가 모두 등장하면 이 표시가 사라집니다. 정답 전용 키워드는 기존 **(정답 전용)** 표시를 유지합니다.

## 키워드 묶음별 정답 카운트
정답 전용(-)을 제외한 모든 키워드를 각각 한 번씩 맞혀야 카드의 정답 카운트가 1 올라갑니다. 같은 키워드를 여러 번 맞혀도 나머지를 대신하지 않습니다. 모두 맞히면 부분 기록을 비우고 다음 1회를 시작합니다. 문제 후보가 하나뿐이면 O 한 번으로 1회가 됩니다.

일부만 맞힌 상태에서는 기존 진한 파란 동그라미 다음의 **한 개만 연한 파랑**으로 표시합니다. 모두 맞히면 진한 파랑 1개가 늘어납니다. 부분 기록은 X, 시간 감소, 새로고침 및 백업·복원에도 유지됩니다. 5회 미만인 카드는 입력 내용을 수정하면 부분 기록을 초기화하고 완료한 횟수를 유지합니다. 5회 이상 카드의 수정 규칙은 아래와 같습니다. 기존 버전의 완료 카운트는 유지하고 새 부분 기록은 비어 있는 상태로 시작합니다.


## 정답 취소와 안전한 저장
- O를 누르면 다음 카드로 자동 이동합니다. 잘못 눌렀다면 이전 카드로 돌아가 **정답 취소하고 다시 외우기** 버튼을 누르세요. 마지막 카드에서는 자동 이동하지 않고 취소 버튼을 표시하며, **다음 바퀴** 버튼을 눌러야 넘어갑니다. 다음 바퀴가 시작되면 이전 바퀴의 취소 기록은 비워집니다.
- 취소하면 해당 O 직전의 부분 진행, 키워드 출제 제한, 완성 횟수와 감소 시각으로 돌아갑니다. 경과한 시간의 감소는 적용됩니다. X는 정답 취소가 아니며, 아직 O를 누르지 않은 카드에서 오답을 기록하고 다음으로 이동합니다.
- 새 버전의 취소 기록은 새로고침 및 최신 백업·복원에도 보존됩니다. 이전 버전에서 이미 O를 누른 기록에는 취소 전 정보가 없으므로 완성 횟수는 유지하고 부분 진행만 초기화하여 다시 학습하게 합니다. 이 경우 화면에 안내합니다.
- 5회 미만 카드의 수정창에서 입력이 바뀌면 부분 진행 초기화 안내를 표시합니다. 띄어쓰기, 줄 순서, 키워드 추가·삭제, 정답 전용(-), 굵기(*) 모두 같은 초기화 규칙을 적용합니다. 입력을 원래대로 되돌리면 저장 버튼이 비활성화되고 기존 진행도 그대로입니다.
- 카드 추가·수정·삭제, 채점·취소, 이동, 여러 카드 추가, 설정 변경, 복원은 저장 성공 후 적용됩니다. 저장 실패 시 변경 전 상태로 되돌리고 오류를 표시합니다. 추가·수정 및 여러 카드 추가의 입력 내용은 남겨 재시도할 수 있습니다.
- 5회를 채워 다음 바퀴에서 제외될 카드는 관리 목록에 **다음 바퀴부터 제외**로 표시합니다. 현재 바퀴가 끝나기 전에 4회 이하로 감소하면 다음 바퀴에도 남습니다. 제외 대기 상태도 새로고침과 백업·복원에 유지됩니다.
- 카드가 10,000개를 초과하면 학습 화면과 설정에 백업 불가 경고를 표시합니다. 카드 10,000개 또는 백업 파일 10MB 한도를 넘는 다운로드는 차단합니다.
- 미해결 오류와 보류 사항은 `KNOWN_ISSUES.md`에 기록했습니다.


## 5회 이상 카드 수정
- 저장 시점의 시간 감소를 먼저 반영한 뒤에도 5회 이상이고 새 문제 키워드가 생기면, 현재 정답 횟수를 4회로 내려 학습에 복귀시킵니다. 누적 정답 횟수와 다음 감소 시각은 유지합니다.
- 수정 후에도 그대로 남은 기존 문제 키워드는 정답 처리합니다. 새로 추가되거나 글자가 바뀐 문제 키워드, 정답 전용에서 문제 후보로 바뀐 키워드만 남은 학습 대상으로 봅니다. 굵기와 순서는 같은 키워드인지 판단하는 데 영향을 주지 않습니다. 입력 시 제거되는 앞뒤 공백은 새 키워드로 보지 않습니다.
- 남은 문제 키워드를 모두 맞힐 때까지 이미 정답 처리된 키워드는 새 문제로 뽑지 않습니다. 관리 목록에는 **(정답 처리됨)**을 표시하며 부분 진행은 연한 파란 점으로 표시합니다. 완료하면 1회를 올리고 일반 출제 규칙으로 돌아갑니다. 정답 취소·새로고침·백업 복원에도 이 상태를 유지합니다.
- 새로 외울 문제 키워드가 없으면 기존 횟수를 유지합니다. 삭제·순서·굵기만 바꾸거나 정답 전용 키워드만 추가한 경우가 여기에 해당합니다.
- **4회로 내려갈 변경이 있을 때만** 수정창에 안내를 표시합니다. 새 문제 키워드가 없는 경우에는 별도 안내 없이 일반 저장 완료 메시지를 표시합니다.
- 재학습 중 다시 수정하면 5회 미만 카드의 일반 규칙에 따라 부분 진행을 초기화합니다.

## 저장 기록 복구
저장 기록에 접근할 수 없거나 형식이 손상되면 학습과 자동 저장을 멈추고 복구 화면을 표시합니다. 예시 카드로 원본을 자동 덮어쓰지 않습니다.

- **원본 내려받기**: 읽어 둔 저장 문자열을 변형 없이 TXT로 내려받습니다. 일반 백업 파일이 아니며, 이후 복구 분석에 사용할 수 있습니다. 브라우저가 저장소 읽기 자체를 막으면 사용할 수 없습니다.
- **백업 복원**: 정상 백업을 선택하고 덮어쓰기를 확인한 후 복구합니다. 복원 취소·잘못된 백업·저장 실패 시 원본을 유지합니다.
- **초기화**: 기존 기록을 지운다는 확인 후 예시 카드로 새로 시작합니다. 저장에 실패하면 원본과 복구 화면을 유지합니다.

자동으로 손상 내용을 추측해서 복구하지 않습니다. 초기화 또는 복원으로 기존 기록을 덮어쓰기 전에 원본을 내려받아 보관할 수 있습니다.
